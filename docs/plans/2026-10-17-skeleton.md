# Start building: milestones + milestone 1 (skeleton)

## Context
The first scope is defined in `docs/product.md` and committed. The repo has docs only: no code, and no Node, Homebrew, Docker or Supabase CLI on the machine. Decisions made while planning:

- Build order: a vertical slice first (chat → plan → menu → list) with fake prices. Real supermarket prices come later.
- Stack: Vite + React + TypeScript PWA (ADR 0002 stays), Supabase for auth, Postgres and server functions, and Claude for the AI nutritionist.
- Supabase: a hosted free project, no Docker.
- Process: a list of milestones, one plan in `docs/plans/` per milestone before coding.
- Tenki credits: used for GitHub Actions CI once tests exist (milestone 5).

This plan does two things: it writes the milestone list, and it builds milestone 1.

## Milestones (written to `docs/notes/milestones.md`)
1. **Skeleton**: Vite React PWA, sign-in with an emailed code, an empty app shell with tabs (Chat, Menu, List, Profile).
2. **Chat**: Supabase Edge Function `chat` → Claude (streaming). Chat UI, chats saved, likes and restrictions saved to the profile, the AI nutritionist rules in the system prompt. Every table migration enables RLS with an owner policy (`auth.uid() = user_id`).
3. **Plan and weekly menu**: the AI produces a structured plan and menu (structured outputs). A menu screen, and swapping a meal by chat or tap.
4. **Shopping list**: a list built from the menu (units as sold, raw vs. cooked, sections), tick off items, share to WhatsApp, copy.
5. **Prices (fake) and store rule**: seeded fake prices for 3 stores, the store rule and savings as a pure function with tests, and CI on Tenki runners.
6. **Pilot ready**: health-data consent, numbers switch, "Order it for me" button, events for the learning table, hosting, real app icons.
- Later: real prices from supermarket websites and SIPC ([ADR 0003](../adr/0003-price-sources.md)).

### Part B: code on `ai-nutritionist` (not committed until you ask)
1. Scaffold with `npm create vite@latest` (react-ts template) **into the scratchpad**, then copy the files into the repo root, leaving out its README. Scaffolding straight into the repo could offer to delete the existing files, including `docs/`. Remove the demo content and assets.
2. `npm i @supabase/supabase-js`. `src/supabase.ts`: one `createClient(import.meta.env.VITE_SUPABASE_URL, import.meta.env.VITE_SUPABASE_PUBLISHABLE_KEY)`.
3. `src/App.tsx`:
   - No session: an email field, which calls `supabase.auth.signInWithOtp({ email })`, then a code field, which calls `supabase.auth.verifyOtp({ email, token, type: 'email' })`.
   - With a session: an app shell with 4 tabs as plain React state (no router yet), placeholder content, and sign out.
   - Why a code and not a magic link: on an installed iOS PWA, a magic link opens Safari, so the session would end up outside the app.
4. PWA: `public/manifest.webmanifest` (name `app` until we pick a name, `display: standalone`, `start_url: /`), a placeholder SVG icon, and the manifest and Apple meta tags in `index.html`. Mark it `shortcut: SVG placeholder icon, add real PNG icons when the app has a name (milestone 6)`.
5. `.env.example` with both `VITE_` variables. The Vite template's `.gitignore` already ignores `*.local`.
6. `.claude/launch.json` with an `npm run dev` config on port 5173, for previewing.

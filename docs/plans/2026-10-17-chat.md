# Milestone 2: chat with the AI nutritionist

Status: **not started**.

## Context
Milestone 1 (skeleton) is on main: a Vite React PWA with sign-in and 4 tabs. Milestone 2 makes the Chat tab real. You talk to the AI nutritionist, it remembers the whole conversation, and it saves your goal, likes and restrictions to your profile ([docs/product.md](../product.md) sections 1–2 and "How the AI nutritionist behaves").

Decisions made while planning:
- The UI is in **Spanish**: all strings in one file. Code and docs stay in English.
- **One ongoing chat** per user, like a WhatsApp thread.
- The Profile tab **only shows** what the AI saved. Changes go through the chat.
- Model: **`claude-sonnet-5-5` at `medium` effort**. This replaces the Opus choice in ADR 0004, so a new ADR records it.

The history is **append-only**: each message's content is stored exactly as the API sent or returned it, thinking blocks included, and replayed byte for byte. That keeps the model's earlier reasoning valid and the prompt cache warm.

## Steps
1. Save this plan as `docs/plans/2026-10-17-chat.md`.
2. `npm i -D supabase`, then `npx supabase init`. In `supabase/config.toml`, set `[functions.chat] verify_jwt = false`, because the function checks the user itself (step 4). That works with the new publishable keys.
3. **Migration** `supabase/migrations/<timestamp>_chat.sql`:
   - `messages`: `id bigint identity pk`, `user_id uuid not null default auth.uid() references auth.users on delete cascade`, `role text check (role in ('user','assistant'))`, `content jsonb not null`, `created_at`. Index on `(user_id, id)`. Rows are ordered by `id`.
   - `profiles`: `user_id uuid pk default auth.uid() references auth.users on delete cascade`, `data jsonb not null default '{}'`, `updated_at`.
   - Both tables: `enable row level security` and an owner policy, `for all using (auth.uid() = user_id) with check (auth.uid() = user_id)`. `on delete cascade` means deleting an account deletes that person's data.
4. **Edge Function** `supabase/functions/chat/index.ts` (Deno, `npm:@anthropic-ai/sdk` and `npm:@supabase/supabase-js`, versions pinned):
   - CORS preflight. A Supabase client built from the caller's `Authorization` header, then `auth.getUser()`, with a 401 if there's no user. All database access goes through this client, so row-level security applies. No service role key.
   - Validate the body as `{ text: string }`, 1 to 4000 characters, with a 400 otherwise.
   - Load the history with `select role, content order by id`, and append the new user turn.
   - Loop, at most 5 rounds: `anthropic.beta.messages.stream({ model: 'claude-sonnet-5-5', system, tools: [save_profile], messages, thinking: { type: 'adaptive', block_binding: { prefix_mismatch_behavior: 'drop_block' } }, output_config: { effort: 'medium' }, fallbacks: 'default', betas: ['server-side-fallback-2026-07-01', 'thinking-binding-controls-2026-08-01'] })`.
     - Text deltas are piped into the response, a `text/plain` stream.
     - On `finalMessage()`, check `stop_reason` before reading the content. On `tool_use`, run `save_profile`, append the `tool_result` turn, and continue.
     - `drop_block`: when we change the system prompt during development, old chats lose their earlier reasoning instead of failing with a 400.
     - The exact SDK calls get checked against the claude-api skill's TypeScript docs while writing the code.
   - All new rows (the user turn, assistant turns, tool results) are inserted **in one go at the end**. If Claude fails midway, nothing is stored, and you can just resend.
   - `save_profile` tool, with `strict: true`:
     - Fields: `goal`, `meals_per_day`, `cooking_time`, `follows_nutritionist_plan`, `nutritionist_plan_notes` (each nullable), plus `cant_eat`, `dislike`, `like`, `want` (string arrays).
     - Its description says "always send the complete profile". The handler upserts `profiles.data` with the input as is: a full replace, so there's no merge logic.
5. **System prompt** `supabase/functions/chat/prompt.ts`: a frozen English constant with no per-user or per-request content, so it caches. It covers:
   - The role, and the 9 rules from product.md.
   - What to ask for: goal, meals per day, cooking time, and whether you follow a nutritionist's plan.
   - The four restriction types, and calling `save_profile` whenever any of it changes.
   - Replying in the user's language, defaulting to Rioplatense Spanish, in short chat-style messages.
   - Menus and lists aren't available yet.
6. **Web app**:
   - `src/strings.ts`: one exported object holding every UI string in Spanish, including the milestone 1 strings.
   - `src/Chat.tsx`:
     - Loads history from `messages` and shows only the `text` blocks (user on the right, AI on the left). Thinking, tool use and tool results are hidden.
     - A textarea and a send button, disabled while waiting.
     - Sending `fetch`es `${VITE_SUPABASE_URL}/functions/v1/chat` with the user's access token and the publishable key, then reads `res.body` with a reader and grows the AI bubble as the text arrives.
     - On an error it shows a message and puts your text back in the box. It scrolls to the bottom.
   - `src/Profile.tsx`: reads `profiles.data` and shows goal, meals, cooking time and the 4 lists under Spanish labels, plus sign out.
   - `src/App.tsx` uses both components and the strings. Bubble styles go in `src/index.css`.
7. **Rule change**: `AGENTS.md` changes "English only, everywhere" to "English only in code, comments and docs. User-facing UI text is Spanish, in `src/strings.ts`."

## Skipped
- Compaction: one chat grows forever. `shortcut: no compaction, add server-side compaction when a chat nears ~150K tokens`.
- A per-user message cap. Cost risk is small with 15 testers, and it belongs in milestone 6.
- Editing the profile in the UI, voice (the keyboard's dictation already works), a Markdown renderer, and testing functions locally (that needs Docker, so we deploy to the hosted project).

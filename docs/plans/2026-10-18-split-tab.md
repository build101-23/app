# A fourth List tab: the cheapest two-store split

## Context
The List tab shows three supermarket tabs ([ADR 0034](../adr/0034-list-shows-one-store-at-a-time.md)), one store at a time. Buying across two stores (Géant and Ta-Ta, say) means flipping between tabs and adding it up by hand. The user wants a fourth option: the cheapest split between two stores, each item at the cheaper of the two.

`planStores` (`supabase/functions/_shared/stores.ts`) already finds that pair, but keeps it only when it saves at least 10% (`split`). So the work is to expose it and draw it as a tab.

Decided with the user:
- The tab shows whenever a real pair costs **less than the best single store, by any amount**, or when no single store has the whole list. Not only at 10%.
- At 390 px the three store tabs stay as they are, and the split is a **full-width row under them**: both icons, "Géant y Ta-Ta", the total.

## Approach
1. **`stores.ts`:** `StorePlan` gets `pair`, the cheapest pair, only when it costs less than `single` (or there's no `single`). `split` is derived from it, with the same rule as today. Tests assert `pair` in the existing cases.
2. **`src/List.tsx`** (the `List` component; the chat's card and what the chat model reads stay as they are):
   - The tab is a `StoreKey` or `'split'`, and the saved pick takes it too. A saved split that no longer exists (crossing items can make it vanish, and the menu version doesn't change) falls back to the recommended store.
   - The fourth tab after the three, when there's a pair: both icons, "Géant y Ta-Ta" (`t.chat.listCard.splitAt`), its total. No pill: one store stays the recommendation ([product.md](../product.md#6-save-money)).
   - On the split tab: the total, per day, budget line and savings card use the pair. Each line shows its product, cost and − + step at the store the pair buys it in. One order button per store, in the actions row and under the list, each with only that store's items.
3. **`src/Order.tsx`:** an optional `ids` prop, passed to `cartFor`.
4. **`src/index.css`:** the split tab spans the grid and lays out in a row; a second compact order button sits next to the first.

Rejected: four equal tabs in one row. At 390 px each is about 83 px wide, so the two icons and "Géant y Ta-Ta" don't fit.

## Check
`npm test`, `npx tsc -b`, `npm run lint`, `npm run build`. In `npm run dev:fixture` at 390 px and wide, in light: the default list (is Géant and Ta-Ta the fourth tab, with the right total, per-line stores and two order buttons), `?cart=split`, `?cart=tata` (no fourth tab), crossing items until the split goes away, and a reload keeping the split pick.

## Results
- Built as planned: `pair` in `planStores`, the split tab and per-store order buttons in `src/List.tsx`, `ids` in `src/Order.tsx`, the full-width tab in `src/index.css`. No new strings: the tab's name is `t.chat.listCard.splitAt`.
- `npm test` (52 pass), `npx tsc -b`, `npm run lint` and `npm run build` pass.
- Checked in `npm run dev:fixture` at 390 px and wide, in light:
  - default list: "Géant y Ta-Ta $ 2.797" under Disco $ 2.722 (1 missing), Géant $ 2.887 (recommended) and Ta-Ta $ 2.482 (3 missing). On it, each line shows Géant or Ta-Ta, the lines add up to the tab's total on all four tabs, the savings card says $ 105, and there are two order buttons: Géant "Muy pronto", and Ta-Ta's link with its 8 products for $ 955;
  - `?cart=split`: the split at $ 2.165; `?cart=tata`: no fourth tab, and a saved split pick falls back to Ta-Ta;
  - crossing out every item bought at Géant: the split goes away and the List falls back to the recommended store; a reload keeps a split pick.
- Not checked: Safari, a screen reader, the real data.
